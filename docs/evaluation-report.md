# P0 评估说明

## 数据集

`evaluations/datasets/fincredit_policy_pilot.json` 包含 30 个政策问答样本：10 个单段直接问题、10 个跨段组合问题、5 个过期/冲突问题、5 个无答案问题。

## 对比方案

- A：纯向量检索。
- B：向量 + 关键词混合检索，并以 RRF 融合。
- C：B 的基础上增加一次受控查询改写。

脚本 `evaluations/run_policy_rag_eval.py` 输出 Recall@5、MRR、引用元数据检查通过率、无答案 F1、P95 延迟、实际改写 token 和平均检索轮次。

## 指标定义与适用范围

- `Recall@5`：前 5 条结果覆盖标注来源文档的比例，再按题平均；无标注来源的无答案题在当前实现中记为 1。该指标不直接衡量生成答案质量。
- `MRR`：结合来源与条款匹配，计算首条相关结果的倒数排名，再按题平均。
- 引用元数据检查通过率：检查匹配结果是否具备来源、条款、生效日期；官方来源还需具备 URL。可回答题须存在相关结果。无答案题可能没有引用，因此不能理解为“所有生成答案均有正确引用”。兼容现有输出，脚本 JSON 字段名仍为 `citation_correctness`。
- 无答案 F1：比较标注的可回答性与系统的证据充分性判断；不评估最终回答的逐句事实准确性。
- 表中的输入/输出 Token 仅统计查询改写，未覆盖嵌入或完整对话的总成本。

定义依据：[评测脚本](../evaluations/run_policy_rag_eval.py)。下表保留历史本地结果；本次文档同步未重新运行模型评测。原始逐题 JSON 未公开提交，公开仓库提供数据集、脚本与汇总报告。

## 2026-08-26 本地 P0 基线

运行环境：Windows + Docker Desktop、PostgreSQL 16 + pgvector、百炼
`text-embedding-v4`（768 维）和 `qwen3.7-plus`。固定 30 题在同一政策库、同一代码版本运行；JSON 明细位于本地 `evaluations/results/`，默认不提交仓库。

A/B 以“存在检索结果”作为可回答判断，因此不具备无答案拒答能力；C 增加了范围边界、点名政策版本核验、完整引用过滤和最多一次非思考模式查询改写。C 组 30 题无失败样本，通过该脚本的检索与拒答检查；本页全部系统质量闸门仍需结合权限、计算与故障演练验证。

这些数字是一次本地、免费额度环境的可复现实测基线，不代表生产 SLA。网络、百炼配额、政策库规模和数据库负载变化都会影响延迟。

本次评测同时发现并修复了两项真实数据库边界问题：可空地域/来源参数在 asyncpg 下缺少显式类型，以及 UTC 政策时间戳在中国时区“生效日当天”的日期比较偏差。

## P0 质量闸门

- 过期政策不能作为当前结论。
- 无答案问题必须拒答或转人工，不能编造引用。
- 查询改写不得超过一次。
- 每条政策回答必须有可追踪 citation_id、官方 URL、版本和生效日期。
- DTI/LTV 必须由确定性代码计算，且结果必须要求人工复核。
- 429、超时、连接失败必须结构化降级并带 trace_id。
