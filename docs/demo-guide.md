# FinCredit Copilot 面试演示指南

## 演示前准备

1. 启动 Docker Desktop。
2. 复制 `.env.example` 为 `.env`，填写自己的 `DASHSCOPE_API_KEY`。
3. 执行 `docker compose up -d --build`。
4. 确认首页 `http://localhost:3000`、接口文档 `http://localhost:8000/docs` 可打开。
5. 使用 `data/demo-documents/` 下的合成材料；不要上传真实个人信息。

## 8 分钟演示脚本

### 0:00-0:45 业务问题与产品定位

打开首页。介绍 FinCredit Copilot 不是“聊天机器人批贷款”，而是把材料提取、政策证据、确定性计算、Agent 协同和人工决策串起来的授信辅助平台。

强调四个关键词：多角色 Agent、受控型 Agentic RAG、确定性 DTI/LTV、trace_id 审计。

### 0:45-2:15 正常材料进件

选择客户经理角色，使用 `CASE-01` 的身份证、收入证明和银行流水。展示逐页字段、来源页码、置信度与证据片段。

说明文本 PDF 优先走文本提取，扫描件或低质量页面才进入视觉模型，避免无谓成本。

### 2:15-3:15 异常与人工修订

切换到 `CASE-05` 展示姓名不一致，或使用 `CASE-06` 展示收入证明 20,000 元而流水月均入账 10,800 元。说明 15% 只是内部演示阈值，不是监管口径。

再展示 `CASE-03` 模糊样本进入低置信度人工复核；修订会追加审计记录，不覆盖原值。

### 3:15-4:45 受控型 Agentic RAG

进入审批人员工作台，点击“全国最低首付比例”或“成都公积金贷款”。展示官方来源、发布主体、章节、版本、生效/失效日期与引用。

补充说明：首轮是向量 + 关键词 + RRF；证据不足时 Qwen 最多改写一次查询，仍不足就拒答/转人工。用“历史政策冲突”问题演示失效规则不会作为当前结论。

### 4:45-5:45 确定性评估

在“DTI / LTV 与材料门禁”输入拟申请月供并执行。指出 DTI、LTV 由代码按固定公式计算，页面展示规则版本；LLM 只解释结果，不做算术。

结果只能是“可进入人工决策”“需要补充材料”或“需要人工复核”，不会自动批准或拒绝。

### 5:45-6:45 人工两阶段决策

选择同意、有条件同意、暂缓或拒绝并填写理由。第一次操作只生成带 UUID 的待确认提案；再次明确确认后才写入最终人工决策。

### 6:45-7:30 trace_id 审计

复制评估卡片中的 trace_id，通过 `GET /api/audit/trace/{trace_id}` 展示模型调用、检索、引用、规则计算、人工修订和工作流事件的关联记录。若启用 observability profile，再展示 MLflow trace。

### 7:30-8:00 收束

总结系统通过“证据、规则、权限、人工、审计”五层边界，把生成式 AI 放在适合的位置。明确当前为 P0 面试演示版，下一阶段可接真实 OCR、征信、反欺诈和生产治理。

## 建议截图清单

1. 首页：全名、四个能力标签和合成数据免责声明。
2. 角色登录：借款人、客户经理、审批人员、管理驾驶舱。
3. 正常材料：页级字段、置信度与证据。
4. 模糊材料：低置信度进入人工复核。
5. 姓名不一致：跨材料异常提示。
6. 收入不一致：收入证明与流水差异。
7. 政策检索：全国规则的官方引用与生效日期。
8. 地方政策：成都规则与辖区标识。
9. 历史冲突：失效政策被阻断。
10. DTI/LTV：公式、结果、规则版本与 trace_id。
11. 人工决策提案：UUID 与二次确认提示。
12. 审计详情：跨阶段 trace bundle 或 MLflow。

## 失败演练

模型超时、429、向量库不可用、政策过期、证据不足和材料缺失的演练步骤见 `docs/failure-drills.md`。
